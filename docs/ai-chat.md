# AI 对话与内部架构

miot 仍以一个插件安装。音乐口令和 AI 问答独立启用；现有 AI 口令分析、点歌记忆、搜索、定时任务和 DLNA 保留。

## 开始使用

设置 → **AI 设置**：在「默认模型连接」集中配置服务商、API 地址、密钥和默认模型；「AI 口令分析」与「AI 对话」分别启用。对话部分启用问答，选择复用默认模型连接或配置独立 API、密钥及模型，然后保存。复用连接无需打开口令分析开关；问答模型留空时使用默认模型。默认连接保留原有配置键，无需重新填写。语音设置页只保留监听、规则、点歌记忆和搜索，并提供 AI 设置快捷入口。语音问答需要开启对话监听，也可以关闭播报，用页面上的文本提问测试模型。

新配置默认每轮说「请问……」「问一下……」进入问答，包括上一轮仍在生成或播报时。可开启「允许连续追问」：回答播报完成后开启追问窗口（默认 60 秒，0 关闭），窗口内可以省略触发词，仍需唤醒音箱。关闭连续追问立即停止使用已有窗口；取消、失败或播报未确认不新开窗口。旧配置按原追问秒数迁移：大于 0 保留开启，0 保持关闭；保存后的明确选择不再被迁移覆盖。固定音乐控制优先，音乐规则、点歌记忆和 AI 口令分析识别的请求交给音乐服务；已识别但播放失败不会再转为聊天。

「无需触发词也交给 AI」（原名「音乐口令未命中后交给 AI」）与触发词、连续追问并列显示，默认关闭。开启后，天气、闲聊等未识别为音乐指令的语音都会进入 AI 对话，不受连续追问开关和窗口限制；它并非点歌搜索失败后的兜底。要让 AI 仅通过触发词进入，请同时关闭此项和「允许连续追问」。旧配置保留开关值，保存后生效。

语音分流和音乐规则统一优先使用对话记录中的原始提问 `question`，仅在其缺失或为空白时使用 `intention.query`。云端意图文本可能去掉「请问」等触发词，不能优先用它分流；歌曲名称内的触发词也不应把点歌转为问答。

AI 口令分析连接已配置，且请求有明确音乐线索（如「播放…」「点播…」「来一首」「听两首」，或请求来点音乐、歌曲、歌单、专辑）时，超时、网络或响应解析失败才由音箱提示「暂时没能识别这条指令，请再说一次」。开关灯、问时间、天气及无法确定音乐意图的普通请求保持静默，继续由小爱处理；仅启用分析但未填写 API 地址或密钥也不播报错误。未匹配消息仍保留智能续播。若聊天兜底或已开启的有效追问窗口会接手该消息，则直接进入聊天，不额外播报这条提示；新操作取消后的旧请求不会迟到播报。

外部歌曲搜索会先将关键词及 title/artist 提示中的连续空白压成单个空格。源明确未命中（HTTP 成功且业务 `code=404` 或 `code=0,data=null`）后，才用去空白变体重试一次；首次命中保留英文词间空格。两次尝试共享该源配置的超时，不改变源优先级；网络、认证和服务端错误不触发这次重试。

「停止回答」「退出对话」「结束对话」取消回答并关闭追问窗口，安全停止后可恢复音乐；「停止播放」保持音乐停止。新问题取消旧任务，旧模型响应不会迟到播报。

## 测试模型连接

「对话模型与角色」主界面显示模型、联网搜索及测试按钮。「连接方式」和自定义请求头收在高级设置，普通连接无需调整。自定义服务首次开启联网搜索时，会为当前草稿选择 Responses 搜索工具模式；高级设置中仍可手工选择连接方式。旧配置保留的搜索偏好若与当前连接方式不兼容，会显示「启用搜索连接」操作。

- **测试连接**：用当前填写的地址、密钥、模型和请求头发送一次简短提问，不启用搜索工具。
- **测试联网搜索**：开启搜索后可用，发送一次实时问题。只有 Responses 成功响应中出现已完成的 `web_search_call` 才显示「已收到搜索完成记录」；有回答但没有完成记录时显示「本次搜索未确认」。百炼 Chat Completions 当前未解析搜索完成元数据，因此不会把正常回复显示为已确认搜索。

测试无需先保存、启用 AI 对话或选择音箱，不打断播放，不写入聊天历史、偏好或配置。测试可能产生模型或搜索费用。测试结果只适用于当前连接，修改相关字段后清除，离开页面后的迟到结果不会显示。失败时给出地址/连接方式、密钥权限或超时的检查提示；用户仍需点击「保存设置」应用修改。

## 自定义请求头

「默认模型连接」和问答的「独立连接」均支持可选的「自定义请求头」，填写 JSON 对象，例如：

```json
{"x-opencode-session":"11111111-2222-4333-8444-555555555555"}
```

默认连接修改后自动保存；独立连接需点击「保存设置」或「保存并获取模型」。复用默认连接时同时复用它的请求头，不合并独立连接的头。请求头用于相应连接的模型列表、流式/普通问答、摘要、记忆提取和口令分析。留空或 `{}` 清除，旧配置默认不添加。

对象的值必须是字符串，头名称不区分大小写，禁止重复名称、控制字符及覆盖 `Authorization`、`Content-Type`、`Host`、`Content-Length`、`Transfer-Encoding`、`Connection`、`X-Fetch-Timeout-Ms`。密钥继续填写在 API 密钥字段；自定义头值会从请求错误和日志中脱敏。格式错误时显示提示，不保存无效输入。

接口字段为默认连接的 `ai_config.custom_headers`（`POST /config`）和独立问答的 `custom_headers`（`PUT /chat/config`），均为字符串键值对象。需要会话头的网关可在这里填写稳定的会话值；[OpenCode 官方说明](https://opencode.ai/v2/docs/console/go/#where-can-i-use-it)要求每段对话使用稳定的 `x-opencode-session`，插件不会自动随机生成或更改该值。

## 联网搜索

「对话模型与角色」可以选择 `Chat Completions` 或 `Responses` 协议。新配置与旧配置升级均默认使用 Chat Completions，避免改变已有服务商和模型的调用方式。协议仅影响问答、摘要和记忆提取；口令分析仍使用原接口。复用默认模型连接时复用地址、密钥和请求头，问答协议独立选择。

- **Chat Completions**：请求 `<API 地址>/chat/completions`，支持现有 OpenAI 兼容服务。开启联网搜索后，仅对百炼官方 DashScope（含国际、美国端点）及工作空间 `*.maas.aliyuncs.com` 地址发送 `enable_search: true`。其他地址下搜索开关不可操作，保留原偏好。
- **Responses**：请求 `<API 地址>/responses`，支持自定义地址。API 地址填写版本前缀，例如 `https://example.com/v1` 或火山方舟的 `https://ark.cn-beijing.volces.com/api/v3`，不要填写完整端点。开启联网搜索后发送 `tools: [{"type":"web_search"}]`；关闭后不声明工具。服务商、模型和网关必须实际支持 Responses 及其服务端搜索工具，仅有 Chat Completions 或独立搜索接口不够。

联网搜索默认关闭，仅用于问答，摘要、记忆提取及口令分析不搜索。开关表示允许模型按需搜索，不保证每轮实际搜索，也不将发送工具声明当作搜索成功的证明。可能产生额外费用，支持情况以服务商文档为准：[百炼](https://help.aliyun.com/zh/model-studio/web-search)。Responses 使用服务商默认思考配置，不复用 Chat Completions 的百炼非思考参数；输出 Token 上限为问答 8,192、后台 4,096，为可能计入输出预算的思考与工具处理预留空间，达到上限按截断报错。

两种协议共用现有超时（最多 30 秒）、流式接收、并发队列和取消机制。接口不支持、搜索失败或超时直接显示错误，不自动切换协议或重试普通问答，以免重复计费或让未搜索的回答被误认为实时结果。Responses 流式回答必须收到 `response.completed`；失败、截断、仅有文本结束事件或连接中断不作为成功，已接收文本可保留查看，不进入成功上下文或播报。没有增量事件但最终完成响应含正文也可正常显示。

Responses 使用 `store: false`，仍由本地管理历史，不使用 `previous_response_id`。因此关闭上下文、清空历史和记忆的语义保持一致；实际远端留存策略以服务商为准。此接口不执行模型自行返回的 function/custom tool 调用，也未接入独立搜索接口。

## 播报与音乐恢复

支持模型 SSE 增量接收，页面在模型生成期间显示当前回答（最多每 200 ms 推送一次）。音箱始终等待完整回答生成后才使用原生 TTS，按句子边界分段，每段最多 200 字，最多播报 1,200 字，完整内容保存在历史中。不会播报模型 reasoning 内容。

「等待时播报提示」默认开启：暂停原音乐并打断原回答后，仅提问设备说「收到，正在思考」。提示与模型请求并行；接管结束时模型已经答完则整段跳过提示，避免它的可闻窗口把回答再推迟。下发提示后保留 3 秒启动保护才播报正式回答，该窗口从下发时刻起算，云端往返已经占用的时间计入其中；提示失败记录告警，不使模型回答失败。可在 AI 设置中关闭，关闭播报的文本测试不发送提示。百炼官方端点的已知混合思考模型与口令分析共用非思考参数，其他服务商及纯思考模型保留原参数；网络、模型和上下文仍会影响响应速度。

页面提问被接受后提示「问题已提交」，当前状态区显示处理进度。历史刷新失败单独显示警告，不将已接受的提问报为提交失败；模型请求和播报失败仍显示真实任务错误。

校验分组与 DLNA 状态、保存恢复位置并取得交互凭证后，模型请求与停止原回答并行；等待提示和正式 TTS 都在接管流程结束后才下发。日志记录任务的模型启动、首段文本、接管完成和播报下发耗时。AI 对话启用时，空闲对话轮询的退避上限缩短为用户间隔与 2 秒中的较大值；未启用时保留 5 秒上限，失败退避不变。云端记录出现的延迟仍不受插件控制。

提问音箱直接执行原有两轮 `pause → stop` 打断，两轮之间等待 2 秒；不再先额外停止一次。其他组员的停止与提问音箱打断并行，避免慢组员延后首次打断；播报仍等待接管任务全部完成。云端应答仅证明命令已受理，实际停止原回答的效果须由对应型号和固件的音箱验证。

问答期间挂起自动切歌，保存原曲进度和播放版本。分组播放时全组暂停，仅提问设备回答，再从共同进度恢复；离线成员单独记录告警。原本暂停或停止的音乐不会自行启动。文本测试替换正在运行的语音问答时，先停止旧回答，再按旧任务的恢复设置处理音乐。

云端返回 `device_data.code=3012`（远程控制超时）时，音箱可能已经播出。插件将其作为下发结果未确认，不立即换接口重发，也不直接将问答标为失败。只有在本轮观察到新的 playing 状态、经过启动保护并收到两次新空闲采样后，才继续下一段或恢复音乐；只有空闲、旧缓存或查询失败不能证明播报完成，90 秒内无法确认则显示「未确认」并保留回答文本、保持音乐暂停。等待提示回执超时也保留 3 秒启动保护。其他失败仍尝试兼容接口；两个接口均失败时保留原有失败处理。

TTS 指令应答只表示接受指令。分段播报有启动保护窗口，使用两次不同时间的新空闲采样确认结束；状态未知或每段超过 90 秒时停止后续段落，保持音乐暂停，需手动继续播放。不同型号固件的播报状态仍需要实机验证。

网页播放、暂停、停止、定时播放、睡眠定时到期、分组变更和 DLNA 接管会作废旧恢复任务。音量调整不取消问答。DLNA 正在接管时需先停止投放才能开始语音问答。

## 历史与长期记忆

聊天数据按账号和设备隔离，使用插件 storage 的独立版本键，和原有点歌记忆分开。新配置默认参考最近 3 轮成功问答，摘要与偏好记忆默认关闭；已有配置升级时保留原轮数、记忆开关及摘要行为。默认保留最多 500 轮历史和 30 天记录，请求参考资料沿用 12,000 字符保护预算。保存聊天记录不等于发送给模型。追问窗口只决定语音分流，不决定历史范围，也不会跨重启恢复。

「携带历史对话」关闭时 `context_turns=0`，不发送旧问答或摘要，也不生成新摘要。开启后可选择最近 1–24 轮，一轮是一次提问和回答。高级设置的「保留更早的对话摘要」独立决定是否参考较早的内容及每新增 8 轮后生成摘要（最多 2,000 字）；生成摘要会产生额外模型请求，关闭历史对话时暂停使用与生成。

「记住我的偏好」独立控制用户事实与偏好的自动提取和使用，也会产生额外模型请求。每设备最多 100 条、每条最多 300 字，按文本相关性最多参考 5 条，不依赖向量库。两类上下文都关闭后仅发送角色提示词和本次问题；关闭选项保留本地记录，删除数据使用独立清理操作。手工编辑不被自动提取覆盖；提取保存处理标记，删除或清空后不会从已处理的旧对话重新生成同一偏好。配置变化和存储版本检查使迟到后台结果失效。

取消和失败任务保留诊断记录，但不作为成功问答加入上下文。删除对话会删除该来源的自动记忆并重建摘要；手工维护的记忆保留。重置会话只清除当前上下文边界与摘要。清空历史、长期记忆和全部数据是独立操作；存储版本检查防止迟到任务重新写入已清空的数据。损坏数据不会被默认值覆盖。

## 接口

以下路径均以 `/api/v1/jsplugin/miot` 为前缀，需要宿主 JWT。设备操作必须提供 `account_id`、`device_id`，且设备已启用管理。新接口直返 JSON，错误为 `{error, detail}`；原接口形态保持兼容。

| 方法与路径 | 用途 |
|---|---|
| `GET/PUT /chat/config` | 问答配置，部分更新；默认关闭 |
| `GET /chat/capabilities` | 返回宿主是否支持增量 HTTP（`streaming`） |
| `POST /chat/test-connection` | `{config: 问答配置草稿, search?: boolean}`；不保存、不操作设备，返回 `{connected, search: not_requested/unconfirmed/completed}`；失败返回错误 |
| `GET /chat/models` | 获取有效问答连接的模型列表 |
| `POST /chat/messages` | `{account_id, device_id, text, speak?}`，返回 202 `{task_id, phase}`；问题最多 2,000 字 |
| `GET /chat/status` | 查询参数指定设备，返回任务阶段、追问窗口与最新回答 |
| `GET /chat/history` | 设备参数与 `offset`、`limit` 分页，返回历史、总数与摘要 |
| `DELETE /chat/history/{id}` | 删除一轮及其自动记忆来源 |
| `POST /chat/cancel` | 设备参数及可选 `close_session`、`resume_music`；默认关闭会话、不恢复音乐 |
| `POST /chat/reset` | 重置会话上下文 |
| `GET/POST /chat/memories` | 列出或手工新增记忆；新增提供 `content` |
| `PUT/DELETE /chat/memories/{id}` | 修改或删除记忆 |
| `POST /chat/clear` | 设备参数与 `range: history/memory/all` |
| `WS /chat/ws` | 设备查询参数，建连快照及任务、回答和数据版本变化推送 |

模型连接支持复用或独立模式；问答、摘要和记忆提取使用问答连接。问答默认超时 30 秒，可设置 1–30 秒；口令分析保留原默认 6 秒。共用请求调度限制两个前台请求、一个低优先级后台请求，同一设备只运行一个前台模型请求。新宿主默认启用实时接收；旧宿主自动使用完整响应，页面提示服务端能力。高级设置可关闭「实时显示回答」以兼容不支持 SSE 的模型接口。流式请求收到完整 JSON 时在同一次请求中处理，不自动重试或重复提问。停止回答、新问题和插件退出会取消活动的流式 HTTP；旧宿主或关闭实时接收时，已发出的普通 HTTP 仍可能运行到宿主超时。流式失败或取消保留已接收部分文本及真实状态，不加入成功上下文。第三方 TTS 作为后续独立方案，本次不增加原生 TTS 提前播报。

## 模块边界与验证

语音监听只接收并提交任务；`VoiceDispatcher` 分流，`MusicCommandService` 承担音乐规则与 AI 分析；旧 `VoiceEngine` 名称作为兼容导出。`PlaybackCoordinator` 管理交互凭证、恢复和接管；`VoiceResumeCoordinator` 按设备管理原有小爱回答后的恢复；`SleepTimerService` 统一网页、语音和定时任务的停止计时。`AIChatService`、`SpeechService`、`ChatMemoryService` 分别负责问答、播报和记忆。

验证：插件目录 `npx tsc --noEmit`、`node --experimental-strip-types --test tests/*.test.mjs`；前端目录 `npm run typecheck && npm run build && npm test`；构建 `songloft-plugin build` 后在 build 目录执行插件 validate。真实播报、打断及分组恢复另需音箱实机验证。

详细覆盖清单与实机验收项见 [AI 对话测试](ai-chat-testing.md)。
