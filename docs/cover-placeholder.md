# 默认封面瞬间插入排查（2026-11-17）

基线为 `19751421dc314cb15b2d0b5c5a7019608cc2dc7a`（v2026.11.17.3）。用户使用 npm run dev 安装，最终明确为“有封面时，默认图标在迷你/全屏播放器、滚动和恢复时短暂闪现”。本批没有继续修改客户端容器或主列表布局；此前保留页面和最终节点身份的检查没有覆盖加载过渡。

## 原因和修复

旧 Cover 的 source 初值为空，解析宿主授权 URL 前、虚拟行回收后重挂载、迷你/全屏封面重新创建时都先渲染 `♫`；自动重试也会先设 failed，再显示该占位。图片最终正常并不能证明过程中没画过错误的默认图。

现在将“有封面，正在解析/重试”与“确实无封面或重试耗尽”分开。前者不画默认图；成功加载的地址在内存复用，重新挂载第一帧就提供已有地址。缓存按服务器、歌曲、原始 URL 版本和尺寸分隔，最多 256 条、单条地址最多 8192 字符；失败立即失效，换歌曲不借用旧图。data URL 直接显示，不额外保留大段 Base64。真正无封面使用项目既有内联 SVG 音符，移除字体字形依赖，保持主题颜色与尺寸。永久失败仍有默认图和下次恢复机会。
