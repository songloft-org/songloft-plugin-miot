# 独立歌曲的临时歌手续播队列

关联 [songloft-org/songloft-plugin-miot#130](https://github.com/songloft-org/songloft-plugin-miot/issues/130#issuecomment-6393443720)。[English](en/issue-130.md)。

## 行为

- 点播不属于任何歌单的歌曲时，先播放匹配歌曲，再续播曲库中同歌手的其他歌曲。新搜索并入库的歌曲、开启「不入库直接播放」的直链歌曲也复用此路径；已配置目标歌单且接管成功时，仍播放目标歌单。
- 队列显示为「歌手: 名称」，沿用临时歌单接口与现有前端列表，可选曲、上一首、下一首。缺少歌手信息或同歌手歌曲时，仅播放匹配歌曲；电台不扩展歌手队列。
- 同歌手候选来自当前歌曲索引（受 `max_song_index` 限制），包含未加入歌单的记录。匹配归一化后的完整歌手署名，也支持 `Eric周兴哲` 与 `周兴哲` 这类带英文前缀或后缀的署名。支持简繁与大小写，保留合唱署名分隔符，按歌曲 ID 去重。候选取自本地索引。
- 读取完整歌曲详情最多并发四次，保留 URL、类型与时长。单条删除/读取失败不阻断点播；停止、新点歌、语音任务取消或外部接管后，迟到的结果不能替换队列。
- 使用设备设置的播放模式：顺序、随机、列表循环继续操作同一队列；单曲循环重复当前歌曲，单曲播放在当前歌曲结束后暂停。
- 已入库队列保存歌手来源、初始点播歌曲 ID 和当前歌曲 ID。重载后重建队列并恢复选择，不自动向音箱推流；网页在同一列表内选曲时保留来源。未入库的临时直链不保存恢复标记，避免重载后重放过期链接。所有临时队列清理旧实体歌单与重载续播锚点。
- 源歌曲没有有效时长时仍由已有设备进度探测判断结束，不凭空设定播完时间。

## 10 月 26 日音箱复测

- 《你，好不好？》三次命中本地 `Eric周兴哲`，生成的顺序队列都是 `total=1`。当其余曲目记作 `周兴哲` 时，旧版的完整字段比较会漏掉它们。日志没有列出整份曲库的署名，实际还缺哪些曲目需用报告人的曲库复核。[复测反馈](https://github.com/songloft-org/songloft-plugin-miot/issues/130#issuecomment-6418357065)
- 两次切歌日志显示，歌曲元数据分别为 297.552 秒和 262.920 秒，设备却上报 310.242 秒和 537.340 秒。后端在曲尾又收到同一首的取流请求，设备进度随后从曲尾回到开头，插件最终等完 30 秒确认宽限才下发下一首。现在用相邻新鲜采样核验回拨时间、稳定流长和曲尾位置。主计时器按较长时长推迟时，尾部探测仍覆盖元数据结尾。设备持续往前播放时，继续按原有规则核验结束。[复测反馈](https://github.com/songloft-org/songloft-plugin-miot/issues/130#issuecomment-6418357065)
- 20:20:23 顺序队列没有下一首，设备回零后已重新取流，旧逻辑只更新插件本地状态。现检测到设备重播时，顺序队尾和单曲播放结束会通过现有设备控制路径停止重播。显式单曲循环和列表循环继续按模式播。若设备端证据只有计时到点或状态不明，沿用保守结束行为。
- 指示灯可在插件设置的「高级设备兼容」中关闭「播放时保持指示灯」。该选项同时关联部分设备的语音播报后原生恢复行为。灯光和语音恢复的实际表现需按机型复测。[指示灯与语音恢复的历史反馈](https://github.com/songloft-org/songloft/issues/171)
