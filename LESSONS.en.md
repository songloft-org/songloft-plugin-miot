### MIOT: Put station MP3 transcoding in the path

- Scope is [songloft-org/songloft#579](https://github.com/songloft-org/songloft/issues/579#issuecomment-7041571686), plugin baseline `41d34b9d0230cd8b359b2f15c6fcf1e67b5eae90`.
- The reported L17A stopped playing when a second query parameter was added. Log redaction covers parameters after the token, and a successful MiNA acknowledgement cannot confirm which URL reached the speaker.
- Probe the MP3 path with HEAD on the local host. When it is supported, put transcoding in the path and send only the access token in the query. Older hosts use the existing query parameter. Regression tests cover the emitted URLs for default, FLV, and HLS stations, the old-host fallback, and a song's format, normalization, seek, and playback speed.
- Device follow-up: installed an instrumented MIoT package with `npm run dev -- --once` against Docker backend dev `6c7a9a23d8cce6779be7dedde2e3e3892e796325`. On the OH2, `player_play_music` preserved `a=1&b=2` in the decoded form sent by the plugin. The MP3 server received `a=1%20b=2`, and playback worked over both HTTP and the configured HTTPS endpoint. The HTTPS comparison used equal 318-character URLs and device progress. Through `player_play_url` the OH2 made no media request with either one or two parameters, leaving direct playback query handling unverified. The host middleware test confirmed that a leading access token allows it to recover space-separated transcode and seek parameters. The installed MIoT package was restored and its checksum verified.
- On L17A firmware 1.108.81 with `player_play_url`, no request arrived for the literal `&` control, and the `%26` variant arrived with a 401. With the token first and `%20` as the delimiter, `/play.mp3` with an extra option and `/play.flv` with `radio_transcode=mp3` both returned 200 and produced audible playback. Apply the encoding in shared MiNA playback preparation for host song routes and round-trippable options. Stations use `/play.mp3` for server-side reconnection. [L17A device logs](https://github.com/songloft-org/songloft/issues/579#issuecomment-7065062224)
- On the local Docker instance, the OH2 used Music API to send GETs to a fixture that returned an empty 404. The single-parameter control and all three `%20`-delimited options arrived intact. Regression tests check both form payloads and host recovery of `format`, `seek`, and `speed`. Automatic encoding in the new build remains to be verified on the L17A.
- Seen 1× (2026-11-21).

### MIOT-037 Fallback track selection must honor the failure cooldown

- The plugin baseline is `de07993b83f955ace9bc540c7d87e42c500985e5`. Release `v2026.11.18.8` has the same player source. See [songloft-org/songloft-plugin-miot#145](https://github.com/songloft-org/songloft-plugin-miot/issues/145).
- `dfb70cf` retried the initial candidate when every candidate was unavailable. In single-track repeat that candidate was the current track. A single URL resolution failure could lead to repeated commands for the same track and trip the three-failure circuit breaker. See `/tmp/songloft-miot-145.4rY5LF/baseline.log` for the isolated baseline regression.
- Handle natural completion and landing failure separately. After a landing failure in single-track repeat, find an eligible track in queue order and repeat that track. Honor the five-minute cooldown during automatic selection, dispatch retries, and prefetch. Stop with a prompt when the queue has no eligible candidate. Explicit playback can retry a track, and confirmed playback clears its marker and the consecutive failure record. Count distinct tracks toward the circuit breaker and report failure to the host as `type=skip`.
- Verification used simulated OH2 all-zero status and a stream probe returning 502. Tests asserted the playback URLs, repetition of the next track, duplicate entries, TTS, timers, and delayed stops. Logs are in `/tmp/songloft-miot-145.4rY5LF/`. The reporter's speaker, firmware, LX Music source, and long-running playback were Not run.
- Review found that a nine-second track with no progress reporting was treated as finished before the ten-second landing check, so the same URL was sent again. The metadata deadline and the landing check share the stream's HEAD request and skip only on a definitive HTTP failure. Status updates and background polling respect the cooldown after stopping. Outdated polling and reload results cannot override newer controls. When dispatch retries run out, clear the old resume anchor and save a new one if the device later confirms playback. Evidence is in `/tmp/songloft-miot-145-review.MaxTlM/`.
- Seen 1× (2026-11-18).
