# DLNA 接收器

在插件的「设置 → 设备 → DLNA 接收器」中填写名称前缀和服务器局域网地址，选择需要的音箱或分组并保存。**总开关与新增目标的独立开关默认都关闭**，只有总开关、目标开关均开启且目标可用时，才广播插件 DLNA 入口。原生已支持 DLNA 的音箱可以关闭插件入口，不影响音箱本身的 DLNA 功能，避免投放列表重复。

每个已管理的独立音箱、每个有效分组分别显示一个入口，名称为「前缀 · 音箱／分组名称」，分组成员不重复出现。分组至少两台音箱，且全部成员存在并已启用管理；未满足条件的分组仍显示开关和具体原因，但不广播入口。这不等于音箱临时离线，离线在实际控制失败时显示错误。空分组和单成员分组不创建分组入口，其已管理成员作为独立音箱。

设备与分组的开关分别持久化。加入分组不会继承音箱的开关，新的分组默认关闭；退组后恢复音箱之前的选择，恢复同一个分组也保留分组选择。关闭总开关不会清空逐项目标的选择。单独关闭一个入口只停止它仍拥有的播放，不影响其它目标或已接管的新歌单。

独立音箱和分组各有持久化的设备 ID、控制路径、播放状态和事件订阅，可以同时投放不同音乐，互不接管。分组身份按分组 ID 保存，重命名或调整成员不会改变设备 ID。新增、移除或关闭音箱管理、调整或解散分组后，接收器随之更新（后台最多约 30 秒）。分组成员变化或解散时，先等待旧投放指令完成并停止旧成员的投放，再更新目标；新的成员不会自动继续旧音乐，需重新投放。关闭接收器只停止它仍拥有的播放，用户已接管的新歌单不会被旧接收器停止。

服务器地址须为手机、电脑和音箱都能访问的 HTTP IPv4 地址，例如 `http://192.168.1.10:58091`。子路径部署可填写 `http://192.168.1.10:58091/music`。使用支持 DLNA 的发送端应用搜索该名称，然后投放 MP3 音乐。手机本地文件须由发送端提供可访问的 HTTP 地址；发送端需保持在线。

接收器通过 SSDP（UDP 多播 `239.255.255.250:1900`）发现。服务器须接入同一局域网并允许多播；Linux Docker 部署建议使用 host 网络。宿主需包含本功能的配套修改（HTTP 对端地址、UPnP 扩展方法及 UDP 地址复用）；旧宿主上设置页会提示升级。全部音箱共用一个 SSDP socket 和 Songloft 的 HTTP 端口，无需按音箱分配端口；插件没有额外监听 8200。共享 UDP 1900 端口要求其它监听服务也允许地址复用，绑定失败会显示启动错误。若与 NAS 自带 DLNA 服务共存时无法发现，应结合启动错误和实际监听端口排查，不能仅凭其它项目的 8200 配置断定本插件端口冲突。

设备描述中的服务 URL 使用以 `/` 开头的路径，保留部署子路径，以兼容直接拼接服务器地址的发送端。发现广播的 `LOCATION` 仍为完整 HTTP 地址。更新插件后，请在发送端重新搜索并选择接收器，避免继续使用缓存的旧服务 URL。

分组的播放、暂停、停止和设置音量会并行下发给全部成员；进度、时长和查询音量以成员列表第一台音箱为参考。并行下发不提供采样级同步，实际起播时间受网络及固件影响。任何成员明确失败时返回协议错误；部分起播或续播失败会尝试停止整组。若任一成员暂停时必须硬停止，整组统一停止，下次播放从头开始。

支持 MP3 的 HTTP/HTTPS 地址；无 `.mp3` 后缀时需提供声明 `audio/mpeg` 或 `audio/mp3` 的 DIDL-Lite 元数据。兼容转义文本及 Flutter `dlna_dart` 直接嵌套 XML 的元数据写法，保留原有命名空间和实体编码。音箱直接拉取原地址，接收器不入库、不下载、不转码。支持播放、暂停、停止、音量、媒体/进度查询，以及 AVTransport、RenderingControl 和 ConnectionManager 的事件订阅。进度取自音箱报告，设备不报告时可能显示 0。若固件忽略暂停而必须停止，状态会显示「已停止」，下次播放从头开始。首版不提供 Seek、自动下一首、静音或 AirPlay。

投放、播放、暂停或停止失败时，设置页会显示动作、UPnP 错误码和原因；所有 SOAP 错误也会以 `[DLNA] SOAP fault` 写入后端日志，包含服务、动作、错误码和协议错误原因，不记录媒体 URL 或元数据。投放失败后紧接着出现的「没有媒体」错误不会覆盖原投放错误；成功查询、停止或不支持的能力探测也不会清除提示。重新成功投放、播放或保存配置后清除提示。

外部投放仅接管所选独立音箱或分组；接管时会停止原歌单的自动切歌及恢复探测；用户主动播放新歌单时结束该接管。关闭接收器会停止仍由它控制的播放、撤销发现广播并释放 socket、定时器和订阅；不会自动恢复原歌单。

`GET/PUT /api/v1/jsplugin/miot/receiver/config` 是需要 JWT 的管理端点，返回强类型配置及运行状态。配置字段为 `enabled`（总开关）、`enabled_ids`（已选择目标的 `id` 数组，默认空）、`name`（名称前缀）、`base_url`。保存时应保留 GET 返回的隐藏成员 ID，避免丢失退组后的选择；未知目标 ID 返回 400。返回的 `receivers` 数组包含每台接收器的 `id`、`account_id`、`device_id`、`name`、`group_id`（独立音箱为空）、`members`、`enabled`（目标开关）、`available`（配置条件是否满足）、`running`、`state`、`error` 及媒体状态；音箱目标来自已管理设备，不再通过单个 `account_id/device_id` 选择。不可用分组仍在 `receivers` 中，以 `available=false` 和 `error` 说明原因，并保留开关选择。每台接收器统一使用 `/dlna/<id>/*` 协议路径。`/api/v1/jsplugin/miot/dlna/<id>/*` 是免 JWT 的局域网协议端点，校验宿主传入的 TCP 对端地址；不应通过公网反代公开这些路径。事件回调仅允许 HTTP IPv4 地址，且 IP 必须等于订阅请求的 TCP 对端，不跟随回调重定向。

验证命令：后端 `npx tsc --noEmit`、`node --test tests/dlna_receiver.test.mjs tests/player_failures.test.mjs tests/player_transition.test.mjs`；前端 `npm run typecheck`、`npm test`、`npm run build`。真实发送端和音箱的网络可达性、固件暂停行为仍需实机验证。
